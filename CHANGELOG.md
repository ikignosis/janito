## [v4.17.0](https://github.com/joaopinto/janito/compare/v4.16.0...v4.17.0) - 2026-08-01

Changes since `v4.16.0` (2026-08-01).

### Added

- While a prompt is pending, pressing **Enter** now cancels the in-flight request ("interrupt without rollback"): `_run_with_progress_bar()` (`janito/openai_client/client.py`) polls stdin non-blockingly while the "Waiting for response from the API server..." spinner runs (`select` on POSIX, `msvcrt` on Windows, only when stdin is an interactive TTY) and, on an Enter press, sets a shared `cancel_event` that `_stream_response()`/`_consume_stream()` honour between chunks, closing the HTTP stream. It then raises the new `RequestCancelled` exception. Unlike Ctrl+C (`KeyboardInterrupt`), which rolls the conversation history back to the last checkpoint, the Enter-cancel keeps the user's message in the history (`janito/shell/interactive.py` prints "Request cancelled (Enter). The prompt stays in the conversation history."), so the chat continues from where it was interrupted; `/ask` (`janito/shell/cmds/ask.py`) and single-prompt mode (`janito/cli/chat.py`) handle it too (single-prompt exits 130 like Ctrl+C). Added `tests/test_enter_cancel.py` (non-TTY guard, POSIX Enter detection via pty, progress-bar cancel/return/exception semantics, shell history preserved on Enter vs rolled back on Ctrl+C).

- Tool-call cards in the web chat now show an operation summary next to the tool name (`janito/web/frontend/index.html`, `js/chatFormat.js`, `css/tools.css`). The header previously showed only the first-argument `filepath`; it now mirrors the parameters each tool prints via `report_start`, so you see at a glance what the call operates on — e.g. `ReadFile /etc/hosts (lines 1-10)`, `SearchText 'foo' in ./src (+1 more)`, `MoveFile a.txt → b.txt`, `ListFiles ./src (recursive)`, `FindFiles . [pattern='*.py', size >=100B]`, `MoveEmails INBOX → Archive`, `WebSearch janito`, `RunGitHubCLI issue list`. The new `toolSummary(name, args)` helper (`js/chatFormat.js`) builds the summary per tool name from the report_start args (files, Gmail, OneDrive, system, net, janitoweb and skills tools), and falls back to the previous first-argument `filepath` chip for unknown tools; unknown tools with no `filepath` show nothing, and MCP tools (name already in the header) stay unchanged. The chip styling is unchanged (`css/tools.css`, now with a little more room for longer summaries). Added `tests/web/test_web_tool_summary.py` and updated `tests/web/test_web_tool_path.py` (frontend wiring contract).

### Fixed

- The web Settings drawer now actually persists a changed model to `~/.janito/config.json` on Save. Previously, selecting a provider, typing a model and clicking Save only updated the running server in memory (`PATCH /api/config` did `setattr(config, "model", …)` and never wrote to disk), so the change was lost on restart and never landed in `config.json`. The `PATCH /api/config` handler (`janito/web/backend/routers/config.py`) now writes the model per provider under `providers.<name>.model` (mirroring the CLI's `--set model=<name>`), accepting a `provider` field that scopes the value; an empty model clears the per-provider override. The Settings drawer (`janito/web/frontend/js/settings.js`) sends the selected provider alongside the model so it lands under the right provider key, and the Model field is now pre-filled from the *selected* provider's own model (configured override, then built-in default) rather than the running server's model. The new model is mirrored into the running server only when it affects the provider the next prompt actually uses, so the very next prompt uses it with no restart. Added `tests/web/test_web_config_model_persist.py` (persistence, per-provider scoping, server mirroring, override clearing, unknown-provider rejection, frontend wiring) and updated the `tests/web/test_web_settings_save.py` wiring checks.

- The web Settings drawer's provider combo no longer snaps back to the default provider after the drawer's changes are saved: `load()` (`janito/web/frontend/js/settings.js`) now keeps the combo where the user left it when re-baselining (e.g. after a Save), as long as that provider is still in the providers list, and only falls back to the effective/default provider when nothing is selected yet or the current pick left the list. Configuring a non-default provider (editing its model or staging its API key) and saving no longer kicks the selection back to the default. Added `tests/web/test_web_settings_save.py::test_load_keeps_selected_provider_across_rebaseline`.

- The web chat input box no longer swallows submissions: previously, at random times, typing a message and pressing Enter (or clicking Send) did nothing — the text stayed in the box with no observable action. `sendPrompt()` (`janito/web/frontend/js/chat.js`) silently returned early when a response was in flight (waiting/streaming — the Send button was disabled but the Enter key was not) or when there was no active session yet (page still bootstrapping, or the active conversation just deleted). It now surfaces a transient toast explaining why the submission was blocked and keeps the typed text so nothing is lost. The Send button (`janito/web/frontend/index.html`) is now disabled for **every** non-idle status — including `tool_running`, which previously left it enabled even though the server dropped mid-turn prompts. The socket handoff is also attempted **before** the UI commits (pushing the user message / clearing the input), so a failed send ("Not connected to the server") keeps the typed text and shows an error instead of losing it. Finally, the backend (`janito/web/backend/routers/chat.py`) no longer silently discards `prompt` messages that arrive while a turn is streaming: `_await_cancel` queues them into a `pending_prompts` list (shared via `_run_turn`/`_run_prompt_turn`) and the WebSocket main loop processes them after the current turn finishes, so a submission is never lost mid-stream. Added `tests/web/test_web_send_reliability.py` (backend `_await_cancel` queueing contract + frontend wiring: busy/no-session feedback, socket-before-clear ordering, button disabled for all busy states).

### Changed

- The Settings drawer's API-key status line (`janito/web/frontend/index.html`) no longer shows the "Key Changed (pending on save)" badge — a staged API key change is surfaced only by the "API key change pending for …" note while it is unsaved. The status line itself just reports the stored state neutrally ("no key stored for this provider" when the provider has no key set, suppressed while a key is staged so it never contradicts the pending note). Removed the now-unused `.key-status.set` style (`janito/web/frontend/css/drawers.css`).

- The Settings drawer's Model field (`janito/web/frontend/js/settings.js`, `index.html`) now shows the default model as the field's **value**, not a placeholder: when no explicit override is set, the input is pre-filled with the selected provider's fallback model (per-provider configured model first, then the built-in `default_model` — the same resolution the topbar provider switcher uses), so the drawer always communicates which model the next prompt would actually use. The pristine baseline tracks the pre-filled value, so Save still starts disabled; the placeholder is now only a fallback hint for an emptied field (it names the default with a "(default)" marker). Adopting a provider (combo change, staged default) also resolves to the configured/built-in default so the field never goes blank. Updated `tests/web/test_web_settings_save.py` frontend wiring contract checks for the value-based display.

## [v4.16.0](https://github.com/joaopinto/janito/compare/v4.15.0...v4.16.0) - 2026-08-01

Changes since `v4.15.0` (2026-07-30).

### Added

- The **CreateSVG** tool (`janito/tools/janitoweb/create_svg.py`) now accepts optional `view_width` and `view_height` parameters (both defaulting to `500`) to control the display size of the SVG graphic. The web frontend respects them: `chatEvents.js` / `chatHistory.js` carry the size onto the SVG content part, `index.html` forwards it to `sanitizeSvg`, and `chatFormat.js::sanitizeSvg` stamps the requested dimensions onto the root `<svg>` element as an inline style (which wins over the `.svg-card svg` stylesheet rule), so the graphic renders at exactly the requested size instead of its intrinsic/auto size. Added `tests/test_create_svg.py` (defaults, echo, optional-integer schema) and `tests/web/test_web_svg_card.py` (frontend wiring). Closes #27.

- Web session persistence (`janito/web/backend/session_store.py`): every conversation is mirrored to `./.janito/sessions/<session_id>.jsonl` (JSON-lines — a metadata line with `session_id`/`title`/`created_at`/`last_active`/`system_prompt`, then one OpenAI-format message per line, relative to the working directory like `./.janito/changes.jsonl`). `SessionManager` persists on create/rename/delete and after every turn (normal completion, Ctrl+C rollback, error rollback, and F2 restart, via `SessionManager.persist()` called from `janito/web/backend/routers/chat.py` — including the one-shot SSE `/api/chat/prompt` path), and `create_app()` restores the files at startup (`SessionManager.load_from_disk()`), so conversations survive a server restart. Persistence is best-effort (never raises, mirroring the changes/tools-usage trackers) and is skipped entirely under `--no-history`. The frontend now triggers the load of *all* sessions when the page loads: `sessions.js` dispatches a `janito-prefetch-session` event for every listed session, which `chat.js` handles by fetching and replaying each session's stored history (`_prefetchSession` — creates the store without switching tabs, guarded by `store.loaded/loading` so the later `openSession()` reuses it). Added `tests/web/test_web_session_persistence.py` (jsonl shape, per-turn persistence, restore on fresh manager/app, delete/restart/rollback rewrites, `--no-history` opt-out, malformed-file resilience, frontend wiring). Documented under `docs/usage/web-ui.md`. Closes #36.

- Added the **DeepSeek** provider (`janito/provider_config.py`): `deepseek` with default model `deepseek-v4-flash`, 384k context window, and endpoint `https://api.deepseek.com`. Closes #35.

- Provider combo on the chat page (`janito/web/frontend/js/providerSwitcher.js`, `index.html`, `css/layout.css`): the topbar now carries a provider switcher — a `<select>` combo populated with exactly the providers that have an API key stored in `~/.janito/auth.json` (`GET /api/config/providers` → `api_key_set`; the current effective provider is always kept in the list so the selection stays valid). Picking a provider switches it **for the current browser/server session only** via a new `POST /api/config/session-provider` endpoint (`janito/web/backend/routers/config.py`): the change is mirrored into the running server (`WebServerConfig.session_provider`) so the very next prompt already uses it — no restart, no Settings detour — but it is **never written to `~/.janito/config.json`**, so it does not leak into future CLI/web runs and is lost when the server restarts. (Persisting a permanent default remains the Settings drawer's explicit "Set Default" button, backed by `POST /api/config/default-provider`.) The combo selects on the new `effective` flag returned by `GET /api/config/providers` (the provider the next prompt resolves to: the session override, else the persisted `active` default), and the response now also carries a top-level `session_provider`. While the switch is in flight the combo shows a spinner, and the result is confirmed by a transient toast (`ok`/`error`, rendered by the root app component, `css/ui-controls.css`) — on failure the combo reverts to the previous effective provider. The status bar (`statusBar.js`) reloads on the new `janito-provider-changed` event and now reports the effective provider (`status.provider`, which honours the session override, while `active_provider` keeps reporting the persisted default), and the Settings drawer (`settings.js`) dispatches the same event when its Set Default button succeeds (and re-reads the providers on failure), so the combo, drawer and status bar never disagree. The agent loop (`janito/web/backend/agent/loop.py`) resolves the effective provider as `session_provider or --provider or persisted default` for both the API call and the context-window lookup. Documented under `docs/usage/web-ui.md`. Added/updated `tests/web/test_web_provider_select.py` (endpoint shape incl. `effective`, `api_key_set` mirroring the auth store, **session switch is in-memory only and leaves config.json untouched**, default-provider still persists, key-required rejection for both endpoints, frontend wiring). Closes #34.

### Changed

- The Settings drawer's **Save** button (`janito/web/frontend/js/settings.js`, `index.html`) now starts disabled and only enables once the drawer holds unsaved changes: the Model field differs from the value it loaded with, or a different provider was promoted to the default via "Set Default" (which also mirrors the adopted model into the field so it stays in sync with what the next prompt uses). A successful save re-baselines the drawer and disables the button again. Added `tests/web/test_web_settings_save.py` (frontend wiring contract). Documented under `docs/usage/web-ui.md`. Closes #38.

- The Settings drawer now **stages** "Set Default" and "Set API Key" as unsaved changes instead of persisting them immediately (`janito/web/frontend/js/settings.js`, `index.html`, `css/drawers.css`). Clicking "Set Default" or entering a key in the "Set API Key" modal only marks the drawer dirty — a yellow "default pending" badge (with a Cancel action to unstage) and an "API key change pending" note — and arms the Save button; nothing is written to `~/.janito/config.json` or `~/.janito/auth.json` until Save is clicked. One Save click applies all staged changes together in order (default provider via `POST /api/config/default-provider`, model via `PATCH /api/config`, API key via `POST /api/config/api-key`) and then re-baselines the drawer. Closing the drawer discards staged changes. The backend endpoints are unchanged — they still persist when called; the drawer now calls them from `save()` instead of the action handlers. Updated `tests/web/test_web_settings_save.py` (staging contract, no immediate persistence) and `docs/usage/web-ui.md`.

- The chat-page topbar provider combo no longer persists its choice to `~/.janito/config.json`. Switching the provider from the topbar now only affects the current browser/server session (in-memory `WebServerConfig.session_provider`); to change the persisted default, use the Settings drawer's "Set Default" button. Closes #34.

- Reasoning (thinking) cards loaded from a stored session now start **expanded** in the web UI (`janito/web/frontend/js/chatHistory.js`): history replay appends reasoning parts with `open=true`, matching live streaming (`chatEvents.js`), so a reloaded/opened session shows its thinking cards unfolded instead of collapsed. Added `tests/web/test_web_session_persistence.py::test_history_reasoning_cards_start_expanded`.

- `POST /api/config/default-provider` (`janito/web/backend/routers/config.py`) now rejects providers without an API key stored in `~/.janito/auth.json` with `400` ("No API key is set for provider '<name>'…"): promoting such a provider would only make the next prompt fail with an authentication error. The new `POST /api/config/session-provider` endpoint enforces the same guard, and the chat-page provider combo relies on it — its list of selectable providers is exactly the set of providers that can actually be used.

- The shell `/config` command (`janito/shell/cmds/config.py`) now displays the provider's built-in default context window (from `PROVIDER_INFO`, via `get_default_context_window_size_from_provider()`) annotated with `(default)` when the user has not configured an explicit value, instead of printing `(not set)`. It only shows `(not set)` when neither a configured value nor a provider default exists.
- Replaced the `PROVIDER_BASE_URLS` mapping (provider → endpoint) in `janito/provider_config.py` with a richer `PROVIDER_INFO` structure. Each provider now carries `default_model`, `default_context_window_size`, and `endpoint`. Added `get_provider_info()`, `get_default_model_from_provider()`, and `get_default_context_window_size_from_provider()` helpers; `get_base_url_from_provider()` now reads the endpoint from `PROVIDER_INFO`.
- Model and context-window resolution now fall back to the provider's built-in defaults (from `PROVIDER_INFO`) when the user has not configured a value: `resolve_runtime_config()` (CLI) and the web agent loop (`janito/web/backend/agent/loop.py`) use these defaults before applying their own hard-coded fallbacks. The `GET /api/config/providers` web endpoint (`janito/web/backend/routers/config.py`) now also returns each provider's `default_model` and `default_context_window_size`.
- `BaseTool.prompt_user()` (`janito/tooling/base_tool.py`) now renders the question inside a `rich` table (bordered frame, `Question` header/title) on stderr instead of a plain start line, so interactive prompts from the `AskUser` tool stand out in the terminal. The question text is displayed literally (console `markup=False`), so LLM-generated content containing `[brackets]` is never interpreted as rich markup. Added `tests/test_ask_user.py::test_question_printed_inside_rich_table` and `::test_question_inside_table_does_not_interpret_markup`. Closes #37.

### Fixed

- The web sidebar now shows the auto-generated conversation title immediately after the first message is submitted: `chat.js` names a new empty session from the start of the user's first prompt (`Api.renameSession(id, content.slice(0, 60))`, matching the backend auto-title in `janito/web/backend/routers/chat.py`) and tells the sidebar to swap just that session's label in place via a new `janito-session-title` event — `sessions.js::_applyTitle` mutates only that item's `title` reactively (the single `<span>` re-renders) instead of reloading the whole list. Previously the backend set the title server-side but the frontend never refreshed the sidebar, so the tab kept showing "New conversation" until some unrelated reload. Existing conversations keep their stored title (`store.titled` is derived from the fetched title in `_loadHistory`), a restarted (F2) conversation is re-named from its next message, and the manual rename (`sessions.js::rename`) now patches in place too. The in-place patch also removes the sidebar **flicker** the original fix caused: a full `load()` rebuild re-sorts by `last_active` (bumped by the rename) and re-creates every tab. Added `tests/web/test_web_session_persistence.py::test_chat_js_auto_titles_new_empty_tab` and `::test_sessions_js_patches_title_in_place`.
- The web reasoning/thinking card now grows vertically to fit the entire thinking content instead of clipping it behind a fixed `300px` internal scrollbar: removed the `max-height` / `overflow-y` cap from `.reasoning-body` in `janito/web/frontend/css/messages.css` (issue #33). Added `tests/web/test_web_session_persistence.py::test_reasoning_card_grows_with_content`.
- The interactive shell status bar and the `/config` command now report the provider in effect for the current session instead of only the configured default (`janito/shell/interactive.py`, `janito/shell/cmds/config.py`). The session provider (from `--provider`, passed to `InteractiveShell` by `janito/cli/chat.py`) takes precedence, so running `janito --provider deepseek` shows `provider: deepseek` in the status bar even when `~/.janito/config.json` still names another provider (e.g. `alibaba`); without `--provider` the configured default is shown as before. Added `tests/test_shell_toolbar.py` and extended `tests/test_shell_config_cmd.py`.
- Removed the last defensive `try/except ImportError` fallback import (`janito/__main__.py`): the `--web` mode now checks the optional `[web]` extra explicitly with `importlib.util.find_spec()` (fastapi / uvicorn) before importing the web backend, so a missing extra is reported with the same actionable install hint but without relying on a caught `ImportError`. The error path returns exit code `1` (instead of `sys.exit(1)`), matching every other CLI validation failure. Added `tests/test_provider_config.py::test_web_mode_without_extra_prints_actionable_error`.

## [v4.15.0](https://github.com/joaopinto/janito/compare/v4.14.0...v4.15.0) - 2026-07-30

Changes since `v4.14.0` (2026-07-29).

### Added

- `AskUser` system tool: allows the AI agent to prompt the user with a question in the console and receive their answer as the tool result (`janito/tools/system/ask_user.py`). The tool delegates to the existing `BaseTool.prompt_user()` method, handles EOF/KeyboardInterrupt gracefully (returns an empty answer instead of crashing), and echoes back both the question and the user's response. Permission: `r` (read-only — it only reads user input). Added `tests/test_ask_user.py`. Closes #30.
- `/tools` command in the web chat: typing `/tools` in the web input box now renders a formatted, card-based listing of every loaded tool, mirroring the CLI's `/tools` command but styled for the browser (HTML/CSS). The panel groups **Built-in Tools** (each with its colour-coded permission badge), a collapsible **Skipped Tools** section (with skip reasons), and **MCP Tools** from connected services, plus a totals footer (`N tools (X built-in, Y MCP)`). The command is intercepted entirely on the client by a new `ChatCommandsMixin` (`janito/web/frontend/js/chatCommands.js`) — it never reaches the model, so no tokens are spent and the conversation history on the server is untouched. It reuses the existing `GET /api/tools`, `GET /api/tools/skipped` and `GET /api/mcp/tools` endpoints (a new `Api.getMcpTools()` helper was added to `janito/web/frontend/js/api.js`), so no backend changes were required. Added `tests/web/test_web_tools_panel.py` (endpoint contract + frontend wiring). Documented under `docs/usage/web-ui.md`. Closes #29.

### Changed

- The CLI now defaults the context window size to 100k tokens when no `context-window-size` is configured for the active provider (`janito/openai_client/client.py::send_prompt`), so the token-usage summary reports `In: <input>/100k` instead of the bare input count in that case (the web UI still falls back to the bare count when unset).
- Removed defensive `try/except ImportError` fallback imports throughout the codebase: all internal package modules (`auth_config`, `general_config`, `secrets_config`, `provider_config`, `tools_registry`, `mcp_manager`, `tools_usage`, `used_files`, `changes`, `skills_provider`) are now imported directly via relative/absolute package imports in `janito/cli/handlers/` (auth, config, info, secrets, skills, tools), `janito/general_config.py`, `janito/openai_client/client.py`, `janito/tooling/mcp_registry.py`, `janito/web/backend/agent/` (loop, tooling) and the gmail/onedrive tools. The `TOOLS_AVAILABLE`/`MCP_MANAGER_AVAILABLE` feature flags and their stub fallbacks were deleted. Third-party libraries that are hard dependencies (`requests` in `janito/mcp_client/http.py`, `pathspec` in `janito/tools/files/gitignore_utils.py`) are now top-level imports, and all test modules import `pytest` unconditionally. Ruff `line-length` raised from 88 to 120 (`pyproject.toml`).
- Used-files tracking rewritten (`janito/tooling/used_files.py`): instead of mapping each path to the list of tools that touched it, the tracker now keeps two unique, insertion-ordered lists — `READ` and `WRITE`. On a successful tool call whose first argument is `filepath`, the path is appended to `READ` when the tool's declared permissions (the `@tool(permissions="…")` string, resolved via `tools_registry.get_tool_permissions`) contain `'r'`, and to `WRITE` when it contains `'w'`; a tool with only `'x'` (e.g. `RunBashCode`) records nothing, and duplicate filenames are not re-added. The CLI end-of-prompt report (printed before the token-usage summary) was reworked to the new `rich` layout — a cyan `Used files` header, a `----------` rule, then `<n> read : file1, file2` and `<n> write : file1, file2` (counts + comma-separated, CWD-relative paths) — replacing the old `===== Used Files =====` per-path/tool listing. A `read`/`write` line is omitted entirely when its list is empty (so a read-only prompt shows just the `read` line, and vice-versa), and an empty report (no files tracked) still prints nothing. The public API (`record_used_file`, `get_used_files`, `reset_used_files`, `format_used_files`) and the CLI/web wiring are unchanged; `tests/test_used_files.py` was rewritten for the new behaviour. Closes #32.
- Token-usage summary now reports the input tokens alongside the configured maximum (context window) using the `input/max` format, e.g. `In: 1.2k/65.5k`, instead of the bare input count — in both the CLI (`janito/openai_client/client.py`) and the web UI. When no `context-window-size` is configured the summary falls back to the previous `In: <count>` form. The configured limit is threaded through the web agent: `UsageEvent` gained an optional `max_tokens` field (`janito/web/backend/events.py`), `StreamAccumulator.usage_event()` accepts and forwards it (`janito/web/backend/agent/call.py`), `stream_prompt()` passes the resolved `context_window_size` (`janito/web/backend/agent/loop.py`), and the frontend renders `input/max` in both the per-message usage strip and the status bar (`janito/web/frontend/index.html`, `janito/web/frontend/js/chatEvents.js`). Added `tests/test_input_tokens_info.py`. Closes #31.
- Web UI asset cache-busting (`janito/web/backend/app.py`): the index route now fingerprints every local `/js/` and `/css/` reference with the file's mtime (`?v=<mtime>`) before serving, so browsers automatically fetch a fresh copy whenever a frontend file changes — no more stale scripts after an edit.
- `GET /api/config/status` now accepts an optional `?provider=<name>` query parameter (`janito/web/backend/routers/config.py`) to inspect the API-key status of a non-default provider; `active_provider` in the response still reports the true default. The settings drawer (`janito/web/frontend/js/settings.js`) uses this to reload the masked key / endpoint info whenever the provider combobox selection changes.
- Moved the web-app test module to a dedicated `tests/web/` subdirectory (`tests/test_web_tools_panel.py` → `tests/web/test_web_tools_panel.py`) so the FastAPI/frontend tests live under their own namespace; the module's repo-root path resolution was updated accordingly. The full suite still runs via `pytest tests/`.
- `ReadFile` no longer treats a `to_line` past the end of the file as an error (`janito/tools/files/read_file.py`): such values are now clamped to the last available line, so the tool returns all the lines it could read instead of failing. An out-of-range `from_line`, and a `to_line` below `1`, are still errors. Added `tests/test_read_file.py`.

### Fixed

- Cleaned up all remaining Ruff violations left after removing the rule exceptions: reordered module-level imports to the top of the file in `janito/openai_client/client.py`, `janito/shell/interactive.py`, `janito/web/backend/agent/tooling.py`, and the `gmail`/`onedrive` tool packages (`__init__.py`) to satisfy `E402`, and split long lines across `janito/cli/parser.py`, `janito/tooling/skills_provider.py`, the `files`/`gmail`/`onedrive` tools and others to satisfy `E501`. `ruff check .` now passes clean.
- Web UI `/tools` panel reactivity (`janito/web/frontend/js/chatCommands.js`): the tools part is now re-acquired through the Alpine reactive proxy after being pushed into the store, so mutations (`tools`, `loading`, `error`) propagate correctly and the loading spinner resolves instead of hanging indefinitely.

## [v4.14.0](https://github.com/joaopinto/janito/compare/v4.13.0...v4.14.0) - 2026-07-29

Changes since `v4.13.0` (2026-07-28).

### Added

- Changes tracking & `/changes` command: every successful tool call whose first argument is named `filepath` is now logged (tool name + invocation parameters only, never the result) to `./.janito/changes.jsonl` by the new `janito/tooling/changes.py` module (`record_change`, `clear_changes`, `load_changes`, `get_changes_file_path`, `render_changes`). The log is removed before each new prompt is processed (`clear_changes()` is called at the start of `send_prompt`), so it always describes the changes made while handling the *current* prompt.
